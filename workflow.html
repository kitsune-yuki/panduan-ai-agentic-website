Panduan pemula · Tanpa harus jago coding dulu

Bikin website dari nol sampai online, dibantu AI agentic

AI agentic itu AI yang tidak cuma menjawab chat — dia bisa merencanakan, menulis kode, menjalankan perintah, membaca error, dan memperbaikinya sendiri. Tugasmu bukan mengetik kode baris demi baris, tapi memberi arahan yang jelas, memeriksa hasilnya, dan memutuskan. Ini peta jalannya, fase demi fase.

Pembagian peran — ini kuncinya

KamuPemilik ide & pengambil keputusan. Menulis brief, memilih, menguji hasil seperti pengguna asli, memberi feedback.
AI AgentEksekutor. Menyusun rencana, menulis & mengubah kode, menjalankan test, membaca error, dan mengusulkan perbaikan.
BrowserTempat membuktikan. Website belum “jadi” sebelum kamu sendiri membukanya dan mencobanya di HP dan laptop.

Contoh proyek pertama yang ideal

Pilih yang kecil dan selesai, bukan yang besar dan mangkrak:

✅ Website profil / portofolio
✅ Landing page produk atau jasa
✅ Katalog sederhana (menu, daftar layanan)
✅ Tools internal kecil: kalkulator, form, generator teks

Hindari dulu: login + pembayaran + database besar sekaligus. Itu proyek kedua atau ketiga.

Pertama, pahami cara kerja AI agentic

Berbeda dengan chatbot biasa yang sekali jawab selesai, agent bekerja dalam putaran (loop) sampai tugas tuntas. Kamu akan melihat loop ini berulang terus — dan pekerjaanmu adalah mengarahkannya di setiap putaran.

LANGKAH 01

Plan — Merencanakan

Agent memecah permintaanmu jadi langkah-langkah kecil. Baca rencananya dulu sebelum dia mulai — di sinilah salah arah paling murah dicegah.

LANGKAH 02

Act — Mengerjakan

Agent menulis/mengubah file, menjalankan perintah di terminal, dan membangun bagian yang direncanakan.

LANGKAH 03

Observe — Mengamati

Agent membaca hasil: output terminal, error, hasil test. Kamu ikut mengamati dengan membuka hasilnya di browser.

LANGKAH 04

Iterate — Memperbaiki

Kalau ada yang kurang, agent memperbaiki berdasarkan temuan — lalu loop berputar lagi sampai hasilnya benar-benar sesuai maumu.

↻ Loop ini berputar untuk setiap fitur: satu fitur selesai & terverifikasi, baru lanjut ke fitur berikutnya.

Workflow lengkap: 7 fase + persiapan

Ketuk setiap fase untuk membuka daftar tugasnya. Kerjakan berurutan — jangan lompat ke deploy sebelum testing, jangan coding sebelum brief-nya jelas. Di tiap fase ada contoh prompt yang bisa langsung kamu salin.

Daftar tugas

  • Install editor + AI agent. Pilih satu dulu: Cursor, Windsurf, atau ekstensi AI di VS Code — atau agent berbasis terminal seperti Claude Code / Codex kalau sudah nyaman dengan terminal.
  • Install pondasi: Node.js (versi LTS), Git, dan browser Chrome. Minta agent membantumu memeriksa semuanya sudah terpasang.
  • Buat akun GitHub. Untuk menyimpan kode (version control) — ini juga “tombol undo raksasa” dan tempat backup proyekmu.
  • Buat akun platform deploy. Vercel, Netlify, atau Cloudflare Pages — ketiganya punya paket gratis untuk mulai. Hubungkan dengan akun GitHub.
  • Buat folder khusus proyek di laptop, satu folder per proyek. Jangan campur dengan file kerja lain.
  • Latihan 10 menit: minta agent membuat halaman HTML sederhana “Halo, nama saya …” lalu buka di browser. Tujuannya merasakan loop Plan → Act → Observe pertamamu.
Tips: Catat semua akun & password di password manager, bukan di sticky notes. Kamu akan sering berpindah antar layanan ini.

Contoh prompt

Saya pemula. Tolong pandu saya memeriksa apakah Node.js, Git, dan npm sudah terpasang di komputer ini. Jalankan perintah pemeriksaannya satu per satu, jelaskan arti hasilnya dengan bahasa sederhana, dan beri tahu langkah instalasi jika ada yang belum terpasang. Jangan mengubah apa pun tanpa izin saya.

Daftar tugas

  • Jawab 5 pertanyaan dasar: Website ini untuk siapa? Masalah apa yang diselesaikan? Pengunjung harus bisa melakukan apa? Halaman apa saja yang dibutuhkan? Seperti apa tampilan yang diinginkan (beri 2–3 contoh website referensi)?
  • Minta AI mewawancaraimu. Biarkan agent mengajukan pertanyaan klarifikasi sebelum membuat apa pun — jawab dengan jujur dan spesifik.
  • Susun daftar fitur, pisahkan dua tumpukan: “Wajib ada di versi pertama” vs “Nanti saja”. Versi pertama harus kecil.
  • Minta agent menuliskan PRD / brief (Product Requirements Document) dalam file BRIEF.md: tujuan, pengguna, daftar halaman, fitur, dan batasan. Baca dan koreksi sampai kamu setuju 100%.
  • Tentukan kriteria “selesai”. Misalnya: “Pengunjung bisa melihat katalog, klik tombol WhatsApp, dan halaman tampil rapi di HP.” Tanpa ini, kamu tidak tahu kapan harus berhenti mengutak-atik.
Tips: Simpan BRIEF.md di folder proyek. Setiap sesi baru dengan agent, minta dia membaca file ini dulu — agent tidak punya ingatan antar-sesi, file inilah ingatannya.

Contoh prompt

Saya ingin membuat website katalog untuk usaha [jelaskan usahamu]. Sebelum menulis kode apa pun, wawancara saya dulu: ajukan maksimal 8 pertanyaan untuk memperjelas target pengunjung, halaman yang dibutuhkan, fitur wajib, dan gaya tampilan. Setelah saya jawab, tuliskan hasilnya menjadi file BRIEF.md yang rapi berisi: tujuan, target pengguna, daftar halaman, fitur versi pertama, fitur yang ditunda, dan kriteria selesai.

Daftar tugas

  • Buat sitemap sederhana: daftar halaman dan isinya. Contoh: Beranda (hero, keunggulan, testimoni, CTA) · Katalog · Tentang · Kontak.
  • Siapkan konten asli: teks, logo, foto, nomor kontak, alamat. Konten “lorem ipsum” boleh untuk awal, tapi catat apa saja yang harus diganti sebelum online.
  • Pilih arah visual: 2–3 warna utama, satu font, gaya (formal / santai / playful). Tunjukkan website referensi ke agent dan sebutkan bagian mana yang kamu suka — bukan menyalin mentah-mentah.
  • Minta agent membuat wireframe / versi kasar dari halaman utama dulu. Periksa alurnya sebagai pengunjung: apakah jelas harus klik apa?
  • Putuskan kebutuhan teknis: apakah butuh form, database, login, atau cukup halaman statis? Untuk versi pertama, jawaban “statis” biasanya yang paling cepat online.

Contoh prompt

Berdasarkan BRIEF.md, buatkan dulu wireframe teks untuk halaman Beranda: susunan section dari atas ke bawah, isi singkat tiap section, dan tombol apa saja yang ada. Jangan buat kode final dulu. Jelaskan juga alasan susunan itu dari sudut pandang pengunjung yang baru pertama kali datang.

Daftar tugas

  • Minta agent mengusulkan stack (teknologi) beserta alasannya, dalam bahasa sederhana. Untuk website sederhana, framework modern seperti Next.js / Astro atau bahkan HTML statis sudah cukup — yang penting agent menjelaskannya dan kamu paham konsekuensinya.
  • Agent membuat kerangka proyek (scaffolding) dan menginstall dependency yang dibutuhkan.
  • Jalankan proyek secara lokal dan buka di browser (biasanya di alamat localhost). Ini “dapur”-mu — yang online nanti adalah hasil akhirnya.
  • Inisialisasi Git & commit pertama, lalu hubungkan ke repository GitHub. Commit = menyimpan titik aman yang bisa kamu kembalikan kapan pun.
  • Minta agent menulis README.md: cara menjalankan proyek, struktur folder, dan perintah penting. Ini penyelamat saat kamu kembali ke proyek setelah libur panjang.
Tips: Biasakan commit setiap selesai satu bagian yang bekerja, dengan pesan yang jelas (“tambah halaman katalog”). Commit kecil-kecil = mudah melacak dan mudah mundur kalau ada yang rusak.

Contoh prompt

Baca BRIEF.md. Usulkan stack teknologi paling sederhana yang cocok untuk website ini, jelaskan pro-kontranya dalam bahasa pemula. Jika saya setuju, buat kerangka proyeknya, jalankan secara lokal, dan tunjukkan cara saya membukanya di browser. Setelah itu, inisialisasi Git, buat commit pertama, dan tuliskan README.md berisi cara menjalankan proyek ini.

Daftar tugas

  • Kerjakan per fitur, bukan sekaligus. Urutan yang enak: struktur & layout → halaman utama → halaman lain → detail & animasi. Satu permintaan = satu hal yang bisa kamu periksa.
  • Selalu minta rencana dulu untuk tugas besar. “Buatkan rencananya dulu, jangan langsung coding.” Baca, koreksi, baru izinkan eksekusi.
  • Periksa di browser setiap selesai satu fitur. Klik semua tombol, coba di tampilan HP (mode responsif di browser), baca teksnya. Jangan menumpuk 5 fitur tanpa memeriksa.
  • Beri feedback yang spesifik. Bukan “kurang bagus”, tapi: “Judul terlalu besar di HP, tombol WhatsApp harus selalu terlihat di bawah, warna hijau diganti yang lebih gelap.”
  • Commit setelah tiap fitur beres. Kalau eksperimen berikutnya merusak, kamu bisa kembali ke titik ini dalam hitungan detik.
  • Isi konten asli segera setelah struktur jadi — teks dan foto asli sering mengubah kebutuhan layout.
  • Kalau agent “ngeyel” atau berputar-putar: berhenti, minta dia menjelaskan akar masalahnya, atau mulai sesi baru dengan konteks BRIEF.md + ringkasan masalah. Sesi baru sering lebih cepat daripada memaksa sesi yang sudah buntu.
Aturan emas: Jangan pernah bilang “buatkan saya website X” dalam satu prompt raksasa. Pecah jadi: halaman → section → komponen. Hasilnya jauh lebih rapi dan mudah diperbaiki.

Contoh prompt

Sekarang kita kerjakan SATU fitur saja: section katalog di halaman Beranda, sesuai BRIEF.md. Buatkan rencananya dulu dalam 3-5 langkah. Setelah saya setujui, kerjakan, lalu berhenti dan beri tahu saya cara memeriksanya di browser. Jangan mengerjakan fitur lain dulu.

Contoh prompt memberi feedback

Saya sudah memeriksa di browser. Yang perlu diubah:
1. Di tampilan HP, judul hero kepotong — perkecil ukuran font-nya.
2. Tombol "Chat WhatsApp" harus selalu menempel di kanan bawah.
3. Jarak antar kartu katalog terlalu rapat.
Ubah hanya tiga hal itu, jangan ubah bagian lain. Setelah selesai, jelaskan file apa saja yang kamu ubah.

Daftar tugas

  • Uji seperti pengunjung asli: buka setiap halaman, klik setiap link & tombol, isi setiap form sampai selesai. Catat semua yang janggal.
  • Uji di HP beneran, bukan cuma mode responsif. Periksa: teks terbaca, tombol mudah diketuk, tidak ada yang bergeser ke samping.
  • Uji kasus aneh: form dikosongkan lalu dikirim, nama sangat panjang, koneksi lambat, gambar gagal dimuat. Website yang baik tetap sopan menghadapi ini.
  • Laporkan bug dengan lengkap: di halaman apa, langkahnya bagaimana, yang terjadi apa, seharusnya apa — plus screenshot kalau bisa. Minta agent menjelaskan penyebabnya sebelum memperbaiki.
  • Minta agent menjalankan pemeriksaan otomatis yang tersedia di proyek (test, lint, build) dan memperbaiki semua error sampai bersih.
  • Uji kecepatan kasar: halaman utama harus terasa ringan dibuka. Kalau berat, minta agent mengecilkan gambar dan memeriksa penyebabnya.

Contoh prompt melaporkan bug

Ada bug. Di halaman Kontak, saat form dikirim dalam keadaan kosong, muncul pesan error berbahasa Inggris dan halamannya jadi kosong. Seharusnya: muncul peringatan berbahasa Indonesia di bawah kolom yang kosong, tanpa pindah halaman. Jelaskan dulu dugaan penyebabnya, lalu perbaiki, lalu tunjukkan cara saya memverifikasinya.

Daftar tugas

  • Pastikan semua perubahan sudah di-commit & ter-push ke GitHub. Platform deploy akan mengambil kode dari sana.
  • Hubungkan repository ke platform deploy (Vercel / Netlify / Cloudflare Pages), ikuti panduan agent langkah demi langkah. Build pertama biasanya otomatis.
  • Atur environment variable (kunci API, token, dsb.) di dashboard platform — jangan pernah menulis kunci rahasia langsung di kode atau di GitHub.
  • Buka URL production dan uji ulang semuanya di sana — versi online bisa berperilaku beda dari localhost. Klik semua halaman, coba form-nya.
  • (Opsional) Pasang domain sendiri: beli domain, hubungkan lewat pengaturan DNS di platform deploy, tunggu HTTPS aktif. Minta agent memandu arti tiap langkahnya.
  • Bagikan link-nya ke 2–3 orang dan minta mereka mencoba tanpa dibimbing. Catatan mereka adalah bahan Fase 7.
Konsep penting: Setelah terhubung ke GitHub, biasanya setiap kamu push perubahan, website online ikut ter-update otomatis (continuous deployment). Jadi “deploy ulang” cukup dengan commit + push.

Contoh prompt

Saya mau deploy proyek ini ke [Vercel/Netlify/Cloudflare Pages]. Pandu saya langkah demi langkah dari menghubungkan repository GitHub sampai websitenya online. Di setiap langkah, jelaskan apa yang harus saya klik dan apa yang harus saya periksa. Ingatkan saya jika ada environment variable yang harus diatur, dan jangan pernah meminta saya menempelkan kunci rahasia di chat ini.

Daftar tugas

  • Kumpulkan feedback pengguna di satu catatan. Kelompokkan: bug, kebingungan, permintaan fitur.
  • Kerjakan perbaikan dalam batch kecil: satu sesi = satu topik, selalu mulai dengan membaca BRIEF.md, akhiri dengan commit + verifikasi di production.
  • Update BRIEF.md setiap ada perubahan arah — supaya sesi agent berikutnya tidak bekerja dengan peta lama.
  • Pantau hal dasar: website masih online, form masih masuk, tidak ada error baru setelah update.
  • Baru naik level: setelah versi statis stabil, pertimbangkan fitur tundaaanmu satu per satu — blog, login, pembayaran — masing-masing lewat mini-workflow yang sama: brief → build → test → deploy.

Ingat: kamu tidak perlu menghafal sintaks. Yang perlu kamu latih adalah tiga keterampilan: menjelaskan maumu dengan jelas, memeriksa hasil dengan kritis, dan memecah pekerjaan jadi langkah kecil. Sisanya adalah pekerjaan agent.

Bank prompt serbaguna

Prompt-prompt pendek ini berguna di hampir semua proyek dan semua fase. Salin, sesuaikan bagian dalam [kurung siku].

🧭 Memulai sesi baru

Karena agent tidak ingat sesi kemarin.

Baca BRIEF.md dan README.md dulu. Ringkas pemahamanmu tentang proyek ini dan status terakhirnya, lalu tanyakan apa yang mau saya kerjakan hari ini. Jangan mengubah file apa pun dulu.

🔍 Meminta penjelasan

Agar kamu belajar, bukan cuma menerima hasil.

Jelaskan bagian ini seperti saya pemula: apa fungsinya, kenapa dibuat seperti itu, dan apa risikonya kalau diubah. Gunakan analogi sehari-hari, hindari jargon tanpa penjelasan.

🛑 Menghentikan agent yang buntu

Saat perbaikan berputar-putar tanpa hasil.

Berhenti dulu. Jangan ubah kode lagi. Jelaskan: apa sebenarnya akar masalahnya, apa saja yang sudah kamu coba dan kenapa gagal, dan apa 2-3 pendekatan lain yang mungkin. Saya akan pilih pendekatannya.

✅ Meminta verifikasi

Menutup setiap tugas dengan bukti.

Sebelum bilang selesai: jalankan build/test yang ada, lalu buat daftar periksa berisi langkah konkret yang bisa saya lakukan sendiri di browser untuk membuktikan fitur ini bekerja. Sebutkan juga bagian yang belum kamu uji.

Peta alat yang akan kamu temui

Tidak perlu menguasai semuanya di hari pertama. Kenali saja perannya — detailnya bisa ditanyakan ke agent saat kamu membutuhkannya.

Tempat bekerja

AI Coding Agent

Partner utamamu. Contoh kategori produk: Cursor, Windsurf, VS Code + ekstensi AI, Claude Code, Codex.

  • Menulis & mengubah kode
  • Menjalankan perintah terminal
  • Membaca & memperbaiki error
Penyimpanan kode

Git + GitHub

Mesin waktu untuk kodemu.

  • Commit = titik simpan aman
  • Push = backup ke cloud
  • Jembatan menuju deploy otomatis
Mesin di balik layar

Node.js & npm

Menjalankan proyek web modern di laptopmu dan menginstall paket bantuan (dependency).

  • npm run dev = mode latihan lokal
  • npm run build = paket final
Tempat online

Platform Deploy

Vercel, Netlify, atau Cloudflare Pages — mengubah repository GitHub menjadi website ber-URL publik, umumnya dengan paket gratis untuk memulai.

  • Deploy otomatis tiap push
  • HTTPS aktif secara bawaan
  • Bisa pasang domain sendiri
Pembuktian

Browser + DevTools

Tempatmu menguji sebagai pengguna: mode tampilan HP, memeriksa error di console, dan menguji kecepatan muat.

  • Coba di Chrome & HP asli
  • Screenshot = bukti saat lapor bug
Ingatan proyek

File Markdown (.md)

BRIEF.md dan README.md — dokumen teks biasa yang dibaca agent di awal sesi agar konteks proyek tidak hilang.

  • Tulis singkat & spesifik
  • Update tiap ada perubahan arah

Kebiasaan yang membedakan hasil bagus dan hasil berantakan

Teknologinya sama untuk semua orang. Yang membuat hasil akhirnya beda adalah cara kamu mengarahkan agent-nya.

✕ Yang sering bikin pemula frustrasi

  • Satu prompt raksasa: “buatkan website lengkap dengan semua fitur” — hasilnya generik dan susah diperbaiki.
  • Percaya tanpa memeriksa: agent bilang selesai, langsung lanjut — bug menumpuk diam-diam.
  • Tidak pernah commit: sekali rusak, tidak ada jalan pulang.
  • Feedback kabur: “kurang bagus, perbaiki ya” — agent menebak, kamu kecewa, berputar terus.
  • Menempel kunci rahasia di chat / kode: API key yang bocor bisa disalahgunakan orang lain.
  • Lompat fase: deploy dulu, testing belakangan — pengunjung pertamamu yang jadi penguji.

✓ Yang dilakukan pembangun yang efektif

  • Satu sesi, satu tujuan: pecah pekerjaan jadi langkah kecil yang bisa diverifikasi.
  • Minta rencana sebelum eksekusi untuk tugas apa pun yang lebih dari sekadar ubahan kecil.
  • Selalu verifikasi di browser — di laptop dan HP — sebelum lanjut ke fitur berikutnya.
  • Feedback spesifik & terukur: sebutkan elemennya, kondisinya, dan hasil yang diinginkan.
  • Commit kecil dan sering, dengan pesan yang menjelaskan “apa” dan “kenapa”.
  • Jaga BRIEF.md tetap hidup: itulah kontrak antara kamu dan agent di semua sesi.

Template brief — titik awal proyekmu

Salin template ini, isi sebisamu (tidak harus sempurna), lalu tempel ke agent pertamamu bersama prompt wawancara di Fase 1.

BRIEF WEBSITE SAYA

Nama proyek      : [mis. Katalog Batik Laras]
Untuk siapa      : [mis. calon pembeli usia 25-45 yang datang dari Instagram]
Tujuan utama     : [mis. pengunjung melihat katalog lalu chat WhatsApp untuk order]
Halaman          : Beranda, Katalog, Tentang, Kontak
Fitur versi 1    : [mis. daftar produk + foto, tombol WhatsApp, form kontak sederhana]
Ditunda dulu     : [mis. keranjang belanja, pembayaran online, login member]
Gaya tampilan    : [mis. hangat & rapi, warna cokelat + krem, referensi: (tautan website)]
Konten yang sudah siap : [mis. logo PNG, 20 foto produk, teks profil usaha]
Selesai jika     : [mis. semua halaman rapi di HP, tombol WhatsApp berfungsi, sudah online dengan domain sendiri]

Checklist terakhir sebelum bilang “sudah production”

Lewati daftar ini satu per satu di URL online-nya, bukan di localhost.

  • Semua halaman terbuka tanpa error
  • Tampilan rapi di HP dan laptop, tidak ada geser samping
  • Semua tombol & link mengarah ke tempat yang benar
  • Form berfungsi dan hasilnya benar-benar sampai
  • Konten asli sudah terpasang — tidak ada teks contoh tersisa
  • Kontak / WhatsApp / alamat yang tampil sudah benar
  • Judul & deskripsi halaman (untuk Google & saat dibagikan) sudah terisi
  • Favicon / ikon situs sudah terpasang
  • HTTPS aktif (ikon gembok di browser)
  • Kode terakhir sudah ter-commit & ter-push ke GitHub
  • Tidak ada kunci rahasia tertulis di dalam kode
  • Sudah dicoba oleh minimal 1 orang lain tanpa dibimbing

Cara memakai panduan ini: jangan dibaca sekali habis lalu dilupakan. Buka fase yang sedang kamu kerjakan, selesaikan daftar tugasnya, baru pindah. Proyek pertama yang kecil dan benar-benar online mengajarkan lebih banyak daripada sepuluh proyek besar yang berhenti di tengah. Selamat membangun — satu fitur kecil setiap kali. 🚀
